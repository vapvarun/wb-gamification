# Security review - 1.6.8

Scope: `git diff v1.6.7..1.6.8`, 143 commits (integration entry and exit rules, member preferences,
OpenBadges issuer profile, block design settings, contrast, translations, release prep). Two REST
routes were added; no AJAX action was added and no existing `permission_callback` was loosened.

## G1 - Mechanical sweep

`security-sweep.sh`, run on the 1.6.8 head and on a `git archive` of v1.6.7.

| Pattern | 1.6.7 | 1.6.8 | Delta |
|---|---|---|---|
| sql-direct-interpolated (HIGH) | 123 | 125 | +2 |
| nonce-only-auth (MEDIUM) | 1 | 1 | 0 |
| extract-call (MEDIUM) | 3 | 3 | 0 |
| no-abspath-guard (MEDIUM) | 12 | 12 | 0 |
| rest-routes/callbacks (INFO) | 78/119 | 80/122 | +2/+3 |

0 CRITICAL. The sweep does not name lines; every `$wpdb` call added since 1.6.7 was read by hand.
Each binds its values through `prepare()`; the interpolated parts are table names built from
`$wpdb->prefix` (the `idx_action_object` index migration on `wb_gam_points`, its `SHOW INDEX` probe,
the Champion level fallback query with no input) or a fixed-length placeholder list.

## G2 - Authorisation matrix

New routes, proven with `rest_do_request()` on the Docker QA stack (BuddyPress, 1.6.8 build):

| Route | Guest | Other member | Member (self) | Admin |
|---|---|---|---|---|
| `GET /members/{id}/preferences` | 403 | 403 | 200 | 200 |
| `POST /members/{id}/preferences` | 401 | 403 | 200 | 200 |
| `GET /issuer` | 200 (public by design) | 200 | 200 | 200 |

The other member's preferences were byte-identical before and after the refused writes. `/issuer` is
the OpenBadges 3.0 issuer Profile every credential's `issuer.id` resolves to; it returns only the
site name and URL.

Read check: `t2_permissions_check` (target exists and `Privacy::can_view_private_history()`).
Write check: `preferences_write_permissions_check` (target exists; the member themselves, else
`admin_permissions_check()`).

## G3 - Reviewed diff

| Change | Risk surface | Finding |
|---|---|---|
| `MemberPrefs::set()` (`src/Engine/MemberPrefs.php`) | SQL upsert from REST input | Columns come from a fixed list; booleans cast to 0/1; `notification_mode` matched against `NOTIFICATION_MODES` (strict). Table and columns as `%i`, values `%d`/`%s`. Safe. |
| `MemberPrefs::render_controls()` and action `wb_gam_render_member_prefs` | Form on profile pages | Renders only when the requested member is the current user; URL and nonce escaped. A host calling the action for another id gets nothing. Safe. |
| `MembersController::set_preferences()` | REST write | Params intersected with `MemberPrefs::DEFAULTS` before `set()`; no other key reaches SQL. Safe. |
| `RedemptionController` create/update | Admin REST write | Permission callbacks unchanged (admin). New `stock_mode` enum, `is_active` through `rest_sanitize_boolean`, empty title refused with 400. Safe. |
| `ProfilePage` visibility (`wb_gam_profile_publicly_visible`) | Who can open `/u/<login>/` | An unknown login and a private profile answer the same way, so profiles cannot be enumerated. The filter receives the plugin's own decision (default from `Privacy::can_view_public_profile()`) and runs only for logged-in viewers; it is the seam a host community uses to apply its own profile privacy. Verified in QA rounds 2-7. |
| `SettingsPage` per-action enable and BuddyPress rank toggles | Admin options | Inside `handle_save()`, behind `check_admin_referer()`; values are 0/1. Safe. |
| `SetupWizard` redirect | Admin redirect | Opens only on an admin page load by a user with `manage_options`, never on AJAX, cron, REST or WP-CLI. Safe. |
| `ImportRunner` lock and run-here | Admin import | Lock name fixed (`import_<slug>`); a second tab waits on `GET_LOCK` instead of running twice. Admin only. Safe. |
| `ProgressReset` member-meta lookup | Admin reset SQL | `esc_like()` on fixed prefixes, values bound by `prepare()`; the LIKE fragment is built from the constant list size. Safe. |
| Integration exit rules (reverse/restore on delete, trash, reject, refund) | Ledger writes on other plugins' hooks | Each reversal is keyed to the object that paid and runs under the same lock as the award; a member cannot trigger a reversal of another member's award except by acting on their own content, which only reverses their own row. |

## Scanner-visible but safe

- Plugin Check `UnescapedDBParameter` / `UnfinishedPrepare` on `ProgressReset.php` member-meta lookup: literal fragment sized from a constant, values bound.
- Plugin Check `NonPrefixedHooknameFound` on `wb_gam_profile_publicly_visible` and `NonPrefixedVariableFound` on `$wb_gam_bn_post_owner`: both carry the plugin prefix.

## Result

No CRITICAL, no unauthorised read or write, no HIGH reachable by a subscriber. Gate G passes.
