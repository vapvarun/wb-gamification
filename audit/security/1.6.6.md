## G2 - Authorisation matrix

No route was added and no `permission_callback` changed, so the 1.6.5 matrix stands. The three
request-facing files that changed only read the session member's own toast stream:

- `MembersController::get_toasts()` - `get_current_user_id()`; permission: logged in. `/me` route, no target id.
- `SSEController` - user from the validated auth cookie; now starts from `max( last_event_id, cursor( $user_id ) )`.
  A client can only skip its own toasts forward (higher `last_event_id`), never read another member's.
  SSE remains opt-in (`wb_gam_sse_allowed`, default false).
- `HeartbeatChannel` - new boolean input `data[wb_gam][toasts]`; it only decides whether this tick takes
  the session member's toasts. Guests no longer load the broker (fewer unauthenticated admin-ajax hits).

## G4 - WP Vanguard scan

## Scanner-visible but safe (do not re-litigate)

- Plugin Check `DirectQuery` / `NoCaching` on the two new ledger guards: caching that read would defeat the
  once-per guard (a second event seconds later must see the first award). Baselined with this reason.
- Plugin Check `NonPrefixedHooknameFound` on `wb_gam_*`: false positive, `wb_gam_` is the plugin prefix.

## Gate F - Action wiring

No new button, form or AJAX action. The one changed client contract (Heartbeat `data[wb_gam][toasts]=1`
from `assets/js/heartbeat.js`, read in `HeartbeatChannel::heartbeat_received`) was verified live: request
body carries the key, response delivers toasts, and a held page loads no reader.

## Verdict

WP Vanguard scan remain backlog, carried from 1.6.5.
