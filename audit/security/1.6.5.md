## G2 — Authorisation matrix

**Not built for this plugin.** No `audit/route-authority.json` / `RouteAuthorityTest` exists yet.
Substituted with a manual, targeted check of the new/changed write surface this cycle:

- **Import routes** (`src/API/ImportController.php`): `/import/sources`, `/import/{source}`,
  `/import/{source}/progress`, `/import/{source}/resume` require `wb_gam_manage_members`;
  `/import/{source}/undo` requires `manage_options`. No `__return_true` on any import route.
- **Import/undo source scoping** (`ImportRunner::source_class()`, `ImportUndo::prefix_class()`):
  the REST route's `{source}` path segment (`[a-z]+`) never reaches a SQL `LIKE` pattern or a file
  path directly. It is resolved against a hardcoded allowlist (myCred/GamiPress/BadgeOS) first; an
  unknown slug is a 400 before any query runs. `prefix_class()` additionally refuses a class whose
  `KEY_PREFIX`/`BADGE_PREFIX` constant is empty, which is what stops an undo from ever compiling to
  `LIKE '%'` and matching every event on the site. `ImportLedger::like()` also runs every prefix
  through `esc_like()`. Verified by reading the code path end to end; `ImportSourceContractTest`
  already pins the "no prefix may be empty, no two prefixes may be a prefix of each other" invariant
  at the unit level.
- **Delegated capabilities** (`wb_gam_manage_levels`, `wb_gam_manage_submissions`, added this
  cycle): checked on the REST write routes themselves
  (`LevelsController::admin_check()` -> `manage_options OR wb_gam_manage_levels`;
  `SubmissionsController::admin_check()` -> `Capabilities::user_can('wb_gam_manage_submissions')`),
  not only on the admin-menu registration that a site owner sees. A staff account granted only one
  of the two capabilities was verified live (this release's own QA pass, not re-run for this audit)
  to reach exactly one admin page and get 403 on the other's REST routes. Levels' one
  `__return_true` route is the pre-existing public level-ladder read (level names/thresholds are
  public display data on profiles and leaderboards); it is not new this cycle.
- **Leaderboard cursor paging**: an anonymous cursor request is 401 unless
  `wb_gam_leaderboard_anon_paging` opts in; covered by `audit/journeys/release/25-leaderboard-keyset-paging.md`.

No RouteAuthorityTest scaffold this cycle — flagged as backlog, not blocking (0 unauthorised
read/write found in the surface actually reviewed).

## Scanner-visible but safe (do not re-litigate)

- Every `LIKE`/table-name string interpolation across the codebase: table names are
  `$wpdb->prefix` + a literal constant, never request data; values passed to `LIKE` go through
  `$wpdb->prepare()` + `esc_like()`. Annotated `phpcs:ignore` at each site with the same reason.
- `libs/woocommerce/action-scheduler`, `libs/easy-digital-downloads/edd-sl-sdk`: vendored,
  unpatched third-party code. Plugin Check's 322 ERRORs in `libs/` (mostly `TextDomainMismatch`,
  which does not apply to a third-party library's own domain) are not ours to fix; re-vendoring
  loses any local patch.

## Gate F — Action wiring (new/changed UI this cycle)

Import screen (`assets/js/admin-import.js`) is a fully JS-rendered app (`<div id="wb-gam-import-app">`
with no static template buttons — every control is created and bound by the same JS function, so
there is no template-selector-without-a-handler class of bug possible here). Every REST call it makes
(`/import/sources`, `/import/{source}`, `.../progress`, `.../undo`, `.../resume`) matches a registered
route with a real `permission_callback`; nonce handling goes through the shared `admin-rest-utils.js`
`apiFetch` wrapper (`X-WP-Nonce`), the same pattern already used by Streaks/Kudos/Members. Levels page
reuses the pre-existing `admin-levels.js` unchanged; confirmed the localized object name
(`wbGamLevelsSettings`) still matches after the page moved off Settings. The admin-menu reorder
(`SettingsPage::order_submenu()`) is a pure PHP array sort with no JS/AJAX surface. No orphaned
selector, no broken REST/AJAX call, no nonce mismatch found in the reviewed scope.
